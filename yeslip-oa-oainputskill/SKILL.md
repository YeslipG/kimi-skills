# OA 销售采购合同录入

目标是在不重复、不漏录的前提下完成“取数 → 上传 → 填表 → 保存 → 台账核验”。先完整保存并核验第一份，再批量处理后续合同。

## 启动条件

1. 先调用 `kimi-webbridge` Skill，使用用户的 Edge 和现有登录态；不要因为内置浏览器更方便而更换浏览器。
2. 需要原生文件对话框或真实键盘输入时，调用 `kimi-cu-win:kimi-cu`。
3. Windows 下每个 WebBridge 请求都用独立 JSON 文件作为请求体，再用 `curl.exe --data-binary` 发送；请求后立即删除临时文件。不要在命令行内联中文 JSON。
4. 使用固定 session：`oa-sales-purchase-contract-entry`，首批标签组命名为“销售采购合同录入”。未经用户要求不要关闭标签组。
5. 若 OA 未登录或扩展断开，先恢复登录态和连接。未保存的页面丢失时，明确告诉用户从哪一份重新开始。

## 第一步：从磁盘读取合同并建立清单

每次执行都重新读取输入文件，不能凭会话中记住的文件名或图片内容代替。为每份合同记录：

| 字段 | 取值规则 |
|---|---|
| 原文件 | 完整绝对路径和准确文件名 |
| 签订日期 | 文件名开头 6 位数字：`260110` → `2026-01-10` |
| 合同年份 | 默认 `2026`；若用户另行指定则以用户为准 |
| 金额(万元) | 按用户流程取文件名中公司名后小横杠后的元金额，除以 10000；例如 `21376` → `2.1376` |
| 上级编号 | 文件名末尾的 `BGJ-...` 或 `GHG-...` 完整编号，例如 `BGJ-2026-31-019` |
| 省份 | 从文件名中的地理位置推断，写简称，如舟山→浙江、乌苏→新疆、乡宁→山西、周口→河南、富裕/龙江→黑龙江 |
| 合同说明 | 直接看合同图片/PDF 的产品表，概括产品名称、关键型号和数量；不要照抄无关的设备备注 |
| 固定值 | 合同类型=销售采购合同；合同单位及甲方=唐山国华科技国际工程有限公司；乙方=南通厚普机械科技有限公司；付款方式=`开票、挂账、付全款`；文件类型=复印件；份数=4 |

如果文件名与合同正文金额不同，按用户指定的文件名规则录入，并在结果中注明。缺少必填数据时不要猜测；跳过该份并清楚报告，其他合同可以继续。

## 第二步：从门户进入干净的新建页

1. 打开国华科技集团门户：
   `http://114.116.12.172:8899/wui/index.html#/main/portal/portal-10-15?menuIds=0,10&menuPathIds=0,10&_key=z8656k`
2. 用真实鼠标点击“采购合同台账”，再点击右上角“新建”。普通 DOM 点击被拦截或弹出窗口被阻止时，直接使用 KimiCU 真实点击，不要反复尝试同一种失败方式。
3. 不要依赖新建页直达 URL。若显示“暂时没有权限”，返回门户重新从快捷入口进入。
4. 确认是空白新建表单，没有旧附件、旧字段或未关闭弹窗。否则从列表重新新建。
5. 记录操作前台账总数，供最终增量核对。

## 第三步：逐份上传和填表

### 1. 上传附件必须最先进行

- 用真实点击打开“上传附件”的文件选择框。
- 在“文件名”输入框粘贴当前合同完整路径并回车，再点击页面“上传附件”。
- 只选当前一份，不要在文件对话框按 Ctrl+A。
- 以附件列表出现准确文件名和大小为成功依据；“选择文件: 未选择文件”仍显示并不代表失败。
- 若 WebBridge `upload` 或 CDP `DOM.setFileInputFiles` 因权限失败，直接使用上述原生文件框，不要要求用户改扩展设置。

### 2. 按联动顺序填写

固定顺序：合同类型 → 合同年份 → 合同单位 → 甲方 → 乙方 → 金额和签订日期 → 付款方式 → 上级编号 → 省份 → 文件类型 → 份数 → 合同说明。选择合同类型或合同单位可能清空字段，因此不要在它们之前填普通文本。

- 合同类型：弹窗中选择“销售采购合同”，不是“销售合同”。
- 甲乙方：打开弹窗后进入“高级搜索”，输入完整公司名并搜索，双击精确匹配行。唐山国华的结果可能在第二页；需要时翻页。
- 上级编号：搜索完整 BGJ/GHG 编号，勾选结果，再点击“确定(1)”。
- 合同名称通常由合同类型自动带出“工业品买卖合同”，无需修改。
- 只操作当前可见弹窗。页面可能保留多个隐藏弹窗，先用 `offsetParent` 过滤，避免把文字填入旧弹窗。

重复录入时可读取并注入 [scripts/oa-form-helpers.js](scripts/oa-form-helpers.js)，使用 `window.OAInput.fillSelections`、`fillTextDate` 和 `saveAndNew` 减少机械操作。先理解返回结果，失败时按下面的恢复规则处理，不要盲目重复整个流程。

### 3. 日期必须通过日历控件选择

不要只写隐藏字段 `field7070`。打开签订日期日历，按目标年月调整月份，再点击目标日期；确认隐藏值和可见文字都为 `YYYY-MM-DD`。

### 4. 份数必须完成失焦校验

用真实鼠标点击“份数”，用真实键盘输入 `4`，再按 Tab 移出焦点。仅设置 DOM 值、剪贴板粘贴或不移出焦点，OA 可能仍提示“份数未填写”。

## 第四步：保存并防止重复

1. 保存前逐项核对附件、类型、年份、合同单位、甲乙方、金额、日期、付款方式、上级编号、省份、复印件、4 份和合同说明。
2. 第一份点击“保存并新建”后，必须回台账刷新确认：总数增加 1，新记录的日期、金额、甲乙方、省份、摘要均正确，并记下系统生成的 GHI 编号。第一份未验证前不要批量继续。
3. 后续每份点击一次“保存并新建”，等待表单清空。清空且无校验提示才表示保存完成；保存较慢时先等待再读值，不要重复点击。
4. 若出现校验提示，记录尚未保存，修复当前字段后重新核对，再保存。不要新建另一份来绕过错误。
5. 最后一份保存后刷新台账，确认总数 = 初始数 + 成功份数，并核对本批系统编号连续、附件和主要字段完整。抽查至少一条详情，确认上级编号实际保存；列表未显示该列不等于未保存。

## 常见失败恢复

- **弹窗未加载导致 `querySelectorAll` 读取不到元素**：先查看已完成字段，从失败的弹窗继续，延长等待，不要重传附件或重填全部字段。
- **甲方已选中但弹窗未关闭**：确认字段已选中后关闭弹窗，从乙方继续。
- **日期提示未填写**：隐藏值有日期也可能未被控件接受，重新通过日历选择并检查可见文字。
- **份数提示未填写**：真实键盘重新输入 4，按 Tab 失焦后再保存。
- **浏览器关闭或登录失效**：不要假设已保存。先回台账核对，再从第一份未入库合同继续。
- **附件错误或顺序错误导致字段被清空**：不要保存，放弃当前新建页，从列表重新新建。

## 完成汇报

报告成功份数、台账前后数量、本批 GHI 编号范围，以及任何跳过或异常合同。只有全部核验通过才说“无漏录、无重复”；未验证的项目要单独说明。
