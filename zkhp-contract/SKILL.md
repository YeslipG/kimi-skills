# ZKHP 合同生成 Skill（结算单 → 工矿机械产品买卖合同）

## 功能说明
读取结算单 docx 中的**加工表**（≥10 列，含理算发货/时吨价/价格，末尾有合计行）和**单算表**（5 列：名称/单价/数量/总价/备注），套用 ZKHP《工矿机械产品买卖合同》模板，生成填好数据的合同 docx，并同步保存桌面副本。

## 触发条件
- "做成 zkhp 合同"、"按结算单做合同"、"结算单填进合同模板"
- 用户同时提供：`结算单.docx` + `ZKHP合同模板.doc/.docx`
- 文件名形如 `yymmdd项目简称结算单....docx`（如 `261008绿洲15结算单-改材料.docx`）

## 两类合同模板（必须先分清）

ZKHP 合同分**设备合同**和**配件合同**两类，模板结构完全不同，不能混用：

- **zkhp 设备合同**：整套设备（如跳汰机除石除杂系统），附件为"加工表（11列称重计价）+ 单算表（5列）"。用 `scripts/fill_zkhp_contract.py`。参考历史件：`D:\DaliyWork\261009zkhp绿洲15合同508551.docx`
- **zkhp 配件合同**：配件一批（标题形如"工矿机械产品买卖合同（2025年11-12月配）"），附件为**按月分块的配件采购明细表**（7列：序号/日期/项目名称/物品/数量/规格/单价/总价/备注，每月块含 合计→其他加工费→总计 行），主标产品行名称固定"跳汰机配件一批"、备注"详见附件"。本 skill 脚本不适用，需按结构直接填（参考 `contract-from-reconciliation` skill 的月度分块与"运费+管理费+税费并入其他加工费"规则）。模板由用户提供（如 `配ZKHP20251112月配_temp.docx`）

用户说"zkhp设备/设备合同"用前者，"zkhp配件/配件合同"用后者；没说清时先问或按货物内容判断（整机→设备，零件→配件）。

## 使用方式

```bash
python <skill-path>/scripts/fill_zkhp_contract.py \
  "261008绿洲15结算单-改材料.docx" \
  "260825zkhp黑伊2期45合同805615.doc" \
  -o "D:/DaliyWork" \
  --project "绿洲15"
```

| 参数 | 说明 |
|------|------|
| `settlement` | 结算单 .docx 路径（必） |
| `template` | ZKHP 合同模板 .doc/.docx 路径（必） |
| `-o` / `--output-dir` | 输出目录，默认当前目录 |
| `--project` | 项目简称（如 `绿洲15`），写入产品表"备注"。缺省时从结算单文件名提取（去前缀日期、去"结算单"后缀） |
| `--model` | 型号规格。缺省时取项目简称末尾数字推导 `YTS{数字}-W-Z`（如 绿洲15→YTS15-W-Z）；推不出则保留模板原型号 |
| `--date` | 签订日期 `YYYY-MM-DD`，默认**当天** |
| `--keep-number` | 保留模板原合同编号（默认改为 `ZKHP`+签订日期） |

## 核心规则

1. **合同总价** = 加工表合计 + 单算表合计，四舍五入取整（模板惯例：805614.8675 → 805615）。产品表"单价=总价=该整数"，人民币行写 `（小写）￥X元；（大写）中文大写元整；（含13%增值税）；`
2. **签订时间** = 当天（`--date` 可改）；**合同编号**同步改为 `ZKHP`+`YYYYMMDD`，保持两者一致
3. **买卖双方沿用模板**（无锡市中矿洗选设备厂 / 南通厚普机械科技有限公司），不要改动
4. **附件两表逐格替换**：保留模板单元格格式（字体/颜色/高亮/下划线），行数与模板不一致时按模板原型行自动增删；结算单中多行单元格的换行保留
5. **输出文件名** = `{yymmdd}zkhp{项目简称}合同{总价整数}.docx`（如 `261009zkhp绿洲15合同508551.docx`）
6. **缺失信息不中断**：型号等项目简称推不出的字段保留模板原值，交付时明确告知用户哪些字段是推断/保留的，请其确认
7. 脚本结束会自检旧值残留（旧总价/旧型号/旧项目名/旧日期），有残留会打印 `[警告]`

## 交付前检查（必须执行）

脚本只保证文本替换正确，排版需人工（agent）目检：

```bash
soffice --headless --convert-to pdf 输出.docx --outdir <tmpdir>
# 再用 pymupdf 把每页渲染成 png 逐页查看
```

逐页确认：
- 第 1 页：合同编号、签订时间、产品行（型号/单价/总价/备注）、人民币大小写金额
- 第 2 页（加工表）：各行数据与结算单一致、合计正确、无列错位、无数字断行
- 第 3 页（单算表）：合计正确、"总价"列数字不断行（脚本已自动加宽该列，仍需目检）

检查通过后，把最终 docx 复制一份到桌面 `C:\Users\yesli\Desktop\`（同名，已存在则覆盖），然后向用户汇报：主文件路径、桌面副本路径、总价计算式、推断字段。

## 注意事项

- **模板不随技能分发**：模板含双方银行账号、税号等商业信息，且技能目录会同步到公开 GitHub 仓库。每次需由用户提供模板文件；用户没给时，优先复用同目录下历史 zkhp 合同作为模板。
- 结算单若有多余的表（如材质时价表），脚本自动忽略，只取加工表和单算表。
- 加工表"合计"行与单算表"合计"行是总价唯一来源，脚本打印计算式，请与用户核对金额后再交付。
- 空单元格在模板中习惯放全角空格（`　`），脚本原样保留结算单内容，不要全局 trim。
- **数据行名称不得含"合计"二字**（如"运杂费合计"）：脚本会把任何含"合计"的行当作合计行丢弃，导致该行数据丢失但总价仍正确。填结算单时改用"运杂费"等名称。
