# Hermes 按需重流程

只执行与当前任务相关的流程。重流程用于降低关键决策和界面验收的盲区，不用于增加日常小任务的协调成本。

## 冷启动双方案规划

适用于架构设计、复杂工作流、技术选型和关键决策。

1. **独立设计方案 A**：只依据用户原始需求，明确目标、约束、假设、实施步骤、风险、取舍和验收方式。不要先延续既有草稿或惯性方案。
2. **冷启动设计方案 B**：优先新开独立子任务，只提供用户原话、必要上下文和约束，不提供方案 A、草稿或倾向，让其独立提出方案。若无法开子任务，显式重置视角，从完全不同的技术路线或相反约束出发，并确保拟制 B 时不参考 A。
3. **对比并合成**：围绕需求契合度、正确性、实施与协调成本、风险与可逆性、可维护性、验证难度比较 A/B，吸收亮点，形成一版有明确取舍的推荐方案；不要机械折中。
4. **交给人类拍板**：说明推荐方案、主要备选和关键风险。关键方案经人类确认后再写死代码或定稿；日常小决策不启用此流程。

双方案子任务的提示词只应包含用户原始需求及必要事实，不透露 A 的结论，避免锚定。

## 产品与界面状态变化验收

适用于产品、网页、前端、应用界面、交互、视觉和动效的实现与验收。按实际状态变化逐项检查，不只按部件罗列，也不只审查代码。

对以下每个适用状态，实际打开页面或应用并观察，记录证据；不适用项说明原因：

- 出现、消失、移动、变大小、换内容、数值跳动。
- 按下、悬停、聚焦、选中、禁用。
- 加载、完成、为空、出错、重试。
- 页面或尺寸切换、数据刷新、连续操作后的状态保持。

每项都回答：

1. 用户看得懂当前发生了什么吗？
2. 变化是突然跳过去，还是有清楚、连贯的来去过程？
3. 文案、位置、尺寸、数值和反馈是否符合原始需求？
4. 是否出现闪烁、错位、遮挡、状态残留、重复提交或无法恢复？

关键产物完成后，优先新开独立子任务做冷酷挑刺复审；若无法开子任务，显式重置视角。复审时只对照用户原始需求与最终产物，不参考实现者的自我说明，不顺手夸自己。按严重程度列出可复现问题、证据和修复建议；常规边缘偏好不阻塞交付。

## 输出与收敛

- 规划任务交付：推荐方案、A/B 关键差异、取舍依据、风险、验收标准，以及需要人类拍板的节点。
- 界面任务交付：逐项状态验收结果、实际观察证据、已修复问题、未解决问题。
- 最终说明固定包含：做了什么、依据是什么、还有什么没解决。
- 没有实际运行或观察证据的项目标记“未验证”，不得报完成。
