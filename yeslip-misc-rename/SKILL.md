# 合同文件重命名

## 命名格式

```text
YYMMDD-买方简称拼音首字母卖方简称拼音首字母-对方公司全称-合同金额.原扩展名
```

示例：

```text
261028-zsyhp-山西泽晟源科技有限公司-12200.jpg
```

## 字段提取规则

### 1. 日期

- 取合同中的签订日期，转换为六位 `YYMMDD`。
- 例如 `2026年10月28日` → `261028`。
- 不使用文件修改时间、上传时间或当前日期代替合同签订日期。

### 2. 买卖双方简称

- 分别去掉买方、卖方公司名称开头反映地区的部分，如省、市、自治区名称。
- 从地区后面的名称中选取 2–4 个能代表公司的汉字，取拼音首字母并转为小写。
- 优先采用自然、可识别的公司简称，不要机械纳入“机械”“科技”“有限公司”等通用词。
- 按“买方简称 + 卖方简称”的顺序直接拼接，中间不加分隔符。

示例：

- 买方 `山西泽晟源科技有限公司`：去掉 `山西`，取 `泽晟源` → `zsy`。
- 卖方 `南通厚普机械科技有限公司`：去掉 `南通`，取 `厚普` → `hp`。
- 拼接结果：`zsyhp`。
- `北京国华技术有限公司` → `gh`；`江苏韦欧……` → `wo`。

### 3. 对方公司全称

- 从买方和卖方中，选择名称不包含 `国华`、`厚普`、`韦欧` 的一方。
- 使用合同中的公司全称，保留地区和公司后缀，不使用简称。
- 如果双方同时包含或同时不包含这些关键词，无法可靠判断时先确认，不要自行猜测。

### 4. 合同金额

- 取合同总金额的阿拉伯数字，优先核对“合计人民币金额（小写）”或等价合计栏。
- 不使用单个产品的单价或某一行明细金额。
- 不加 `元`、货币符号或千分位；整数不写 `.00`，非整数保留实际小数。
- 例如 `12200元` → `12200`。

## 文件对象与安全流程

1. **锁定用户指定的文件。** 用户上传的是图片，就重命名该图片；用户指定的是 PDF，才重命名 PDF。即使另一份文件内容相同，也不能替代用户指定的对象。
2. **忽略会话附件目录中的副本。** 当用户提供的是 Kimi 会话附件目录中的文件时，不直接修改该副本。使用文件搜索工具查找桌面 `C:\Users\yesli\Desktop` 和当前工作目录（如 `D:\DaliyWork`）中是否存在同名文件，将找到的文件视为用户要修改的原始文件；若存在多个可能位置，列出后请用户确认。若不存在同名文件，则要求用户提供原始文件路径，或先将结果保存到 `D:\DaliyWork` / 桌面后再重命名。
3. 如果用户使用“这个”“刚才那个”等指代，结合当前对话定位此前讨论的上传文件。无法唯一确定原文件时，先询问文件路径，不要按合同内容随意选择其他文件。
4. 执行前从磁盘重新读取源文件，核对合同内容与已提取的信息，以当前磁盘内容为准。
5. 只修改文件名，保留原目录和原扩展名；不转换格式，不额外生成 PDF，不修改文件内容。
6. 重命名前确认源文件存在、目标文件不存在。目标已存在时停止并报告，禁止覆盖。
7. 重命名后核对新文件存在且路径正确。若发现改错对象，先将被误改的文件恢复原名，再处理正确文件。
8. 未经用户明确要求，不批量处理其他合同。

## 完成反馈

简要报告原文件名、新文件名和**完整保存路径**。例如：

```text
已将图片 C:\Users\yesli\Desktop\5721bd82b842666a57fc7b3049667d01.jpg 重命名为：
C:\Users\yesli\Desktop\261028-zsyhp-山西泽晟源科技有限公司-12200.jpg
```

## 自检示例

合同信息：2026年10月28日签订，买方为山西泽晟源科技有限公司，卖方为南通厚普机械科技有限公司，总金额12200元。

- 用户上传 JPG 图片：`261028-zsyhp-山西泽晟源科技有限公司-12200.jpg`
- 用户明确指定 PDF：`261028-zsyhp-山西泽晟源科技有限公司-12200.pdf`

两种扩展名仅取决于被指定的原文件，不能因电脑上同时存在另一种格式而改错对象。
