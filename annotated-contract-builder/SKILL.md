# 三色标注合同生成 Skill（模板 + 说明材料 → 可追溯新合同）

## 适用场景

用户手上有三样东西：
1. **合同模板**：扫描件图片（如 `扫描_*.png` 一个文件夹）、PDF 或 Word——版式和条款框架的来源；
2. **说明材料**：docx 技术说明/安装说明/物料清单（可能含嵌入图片）——详细内容的来源；
3. **改动清单**：口头或文字给出的替换要求（改地点、改金额、改日期、换甲乙方、信息留空等）。

输出一份"留痕"合同：谁都能从颜色看出每段内容来自哪里、被怎么改过。

## 标注规则（核心，判定细则见 references/annotation-rules.md）

| 颜色 | 含义 | RGB |
|------|------|-----|
| 灰 | 模板未改动内容；**或在模板基础上改写的内容**（用户指定的改动：金额、日期、地点、甲乙方信息，以及模板地名/旧值的适配改写） | 808080 |
| 蓝 | 模板内容被**说明材料详细内容替换**的部分（尽量保持材料原文） | 0000FF |
| 绿 | **在说明材料内容基础上的进一步改写**：适配合同语境（投标方→乙方）、补全残句、纠正笔误、修正编号/数量矛盾 | 008000 |

- 标注粒度到 run（同一段可蓝原文+绿改写词混排）。
- 正文开头必须有图例（`ContractBuilder.legend()` 自动生成）。
- 拿不准蓝还是绿时，问自己："这行字是不是材料里原来就这么写的？"是→蓝，不是→绿。

## 标题与目录规则（建设工程合同点分式，每次交付前必查）

**为什么用点分式**：GB/T 9704（党政公文）的 `一、→（一）→ 1.→（1）→①` 七层体系名义上管公文；中国没有专门针对商务合同编号层级的国标。住建部+工商总局联合发布的《建设工程施工合同（示范文本）》GF-2017-0201 使用 **`条 → X.Y → X.Y.Z → X.Y.Z.N` 点分式**，是设备安装、工程施工类合同的事实标准。本 Skill 处理的多为安装/施工/设备类合同，默认采用点分式，全篇一个体系贯穿到底，不混入括号数字/圈码/字母。

1. **统一一套编号体系**（无论内容来自模板还是说明材料，全部编入）：
   - 一级（H1，进目录）：**第X条、小标题** — 黑体四号(14pt)，小标题≤12汉字、末尾无标点
   - 二级（H2，不进目录）：**X.Y 小标题** — 黑体小四(12pt)，末尾无标点
   - 三级（H3，不进目录）：**X.Y.Z 小标题** — 宋体小四加粗，末尾无标点
   - 正文条款：**X.Y / X.Y.Z 编号 + 内容**（非标题，普通正文，用 `clause()` 生成）
   - 条款子项：**点分延伸到下一级**（`X.Y.Z.N`，用 `subitem()` 生成）；不再用 `（1）（2）`、`①②③`、`(a)(b)` 等其他风格
2. **来源文件的原编号一律不进标题体系**：说明材料的 `6.2.1`、`7.1`、`2.1.1` 等全部重编为合同统一编号（如第四条下 4.1、4.2…；第六条下 6.2.1、6.2.2…）。来源编号只能作为正文文字保留，不能做标题或条款前缀。
3. **条款编号的 X 必须与所属第X条匹配**（第四条下只能出现 4.x，不能出现 6.2.x）；子项编号的前缀必须是其父级编号（6.4.1.1 的父级必须是 6.4.1）。
4. **目录只显示一级标题**（TOC 域 `\o "1-1"`），且**必须压缩在一页以内**——放不下就缩字号、调行距（引擎 `toc()` 已内置紧凑 TOC 样式：五号字、单倍行距、段距 0；条目更多时继续调小）。
5. 标题颜色跟随内容来源，标题精简/改名/重编号不改变颜色归属（详见 references/annotation-rules.md）。
6. `scripts/verify_contract.py` 已内置以上检查（标点/字数/条的顺序/条款编号归属/无旧式子项编号），每次交付前必跑；目检时确认**目录只占一页**、正文首页页脚页码为 1。

## 工作流（8步）

### 1. 读取模板

- 图片/PDF 扫描件用 ReadMediaFile 逐页读取。**扫描件会被降采样，关键数据必须再用 `region` 参数按原图坐标局部放大核对**：金额（大小写）、银行账号、税号、支付行号、电话、日期、开户行全称、合同编号——这些错一位就是事故。
- 手写内容（签名、手写地址电话）能辨则辨，不能辨的字段留空并告知用户，不要猜。
- 模板是 docx 时直接 python-docx 读取。

### 2. 提取说明材料

- python-docx 遍历段落与表格全文转录。
- 材料中的嵌入图片用 `scripts/contract_builder.py` 的 `extract_media()` 抽出、`image_anchors()` 定位每张图锚定的段落（"如下图"指的是哪张图），生成时原样嵌回对应位置。

### 3. 确认改动清单

- 金额：小写与大写同时改（240000.00 ↔ 贰拾肆万元整），大小写必须互相匹配。
- 日期："今天"一律用 `date` 命令取本机当天，不要凭会话时间猜。
- 甲乙方替换：旧方的**人**（代表、委托人、账号、地址、电话）一律不沿用到新方；用户没给的新方信息**留空**（只留标签如 `乙方：`），不要把旧值留下。
- 改动清单里没提到的模板内容保持原样（灰色）。

### 4. 编写内容脚本

- 排版机制全部在 `scripts/contract_builder.py`（ContractBuilder 类），内容脚本只写文本与颜色。完整范例：`examples/hlj_yipin/build_hlj_yipin.py`（黑龙江伊品安装合同，含全部三色判断实例）。
- API 速查：
  - `b.cover(title, lines)` 封面（独立节，无页码）
  - `b.toc()` 目录页（独立节，无页码；默认只显示一级标题、紧凑一页版式），随后正文节页码自动从 1 起编
  - `b.legend("《XX说明》")` 三色图例
  - `b.h1/h2/h3(text, color)` 国标标题（H1黑体四号/H2黑体小四/H3宋体加粗小四；第X条→h1，X.Y→h2，X.Y.Z→h3）
  - `b.clause("4.1", (text, color))` / `b.clause("4.10", [(t1, BLUE), (t2, GREEN)])` 带统一编号的正文条款（编号前缀+内容，非标题）
  - `b.para((text, color))` / `b.para([(t1, BLUE), (t2, GREEN)])` 正文（宋体小四、首行缩进2字符、1.5倍行距）
  - `b.image(path)` 嵌入材料图片
  - `b.signature_table([(左, 右), ...])` 双列签署栏
- 标题体系即大纲：h1/h2/h3 用 Word 内置 Heading 样式，目录才有级别。

### 5. 生成 docx

```bash
# 本机 python-docx + pywin32 环境
D:/Kimi/.venv-xlsx/Scripts/python.exe 内容脚本.py
```

### 6. 刷新目录页码 + 导出预览

```bash
D:/Kimi/.venv-xlsx/Scripts/python.exe scripts/update_fields.py 合同.docx --pdf 预览.pdf
```

TOC 域的页码必须由 Word 实际计算（python-docx 写的只是占位符），**这一步不能省**。

### 7. 双重校验

```bash
# 程序校验：必备字段在、旧值全无、三色统计、节/标题/图片数
D:/Kimi/.venv-xlsx/Scripts/python.exe scripts/verify_contract.py 合同.docx \
    --require 新单位名 240000.00 贰拾肆万元整 \
    --forbid 旧单位名 旧金额 旧账号 旧日期
# 目检：渲染封面/目录/正文首页/末页，看颜色、错位、页码、签署栏
D:/Kimi/.venv-pdf/Scripts/python.exe scripts/render_preview.py 预览.pdf 输出目录
```

程序校验必查项：旧单位名、旧人名、旧金额（大小写）、旧账号税号行号、旧电话、旧日期、模板原地名，以及标题规范（一级标题≤12汉字、末尾无标点、第X条顺序连续、条款编号归属正确——`verify_contract.py` 自动检查）。目检必查页：封面、目录页（只占一页、只列一级标题、条目末尾无标点、页码与正文一致）、正文首页（页脚应为 1）、末页签署栏。

### 8. 交付

- 按项目 AGENTS.md 强制规则：成品复制一份到 `C:/Users/yesli/OneDrive/桌面`（同名），核对大小一致。
- 清理过程文件（预览 PDF/PNG、抽取的 media 等）。

## 迭代指南（用户反馈来了怎么办）

1. 只改内容脚本里的文本/颜色/签署栏，排版机制不动；
2. 重跑第 5–7 步；
3. 重新复制桌面副本。
常见迭代：换甲乙方、改金额日期、增删条款、拟/改一级小标题（≤12汉字、末尾无标点；`b.toc()` 目录默认只列一级标题）。

## 常见坑（都是踩过的）

- **Git Bash 的 `/tmp` 对 Windows 版 python 不可见**：解压 docx 取图片时，输出目录用工作目录下的路径，别用 `/tmp`。
- **扫描件降采样**：ReadMediaFile 默认会压缩大图，金额账号必须 `region` 放大核对原图。
- **会话时间不一定是当天**：系统给的会话时间可能过期，"签约时间改成今天"用 `date` 取真值。
- **旧方人员信息污染**：换了甲方后，原甲方代表（人名）不能留——人属于旧单位。
- **说明材料的原文不等于正确**：材料里的笔误、残句、编号错位、数量矛盾要修正并标绿，不要照抄（标蓝的是"照抄"的部分）。
- **Word COM 保存后 run 会被拆分**，颜色统计数会变多，属正常现象，看颜色种类不看绝对数。
