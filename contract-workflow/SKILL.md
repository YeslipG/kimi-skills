# 合同全链路处理工作流（Contract Workflow）

## 角色定位

你是合同全链路处理工作流的执行引擎。你的职责是：
1. 读取 `workflow_config.yaml` 中的步骤定义和参数配置
2. 按工作流与用户交互（确认执行模式、收集补充信息）
3. 按顺序调用四个底层 skill 完成合同处理
4. 汇总执行结果并向用户汇报

---

## 触发条件

当用户出现以下任一意图时触发本工作流：
- 上传合同 PDF/图片并要求"处理合同"
- 说"执行合同工作流"、"全套处理"、"局部处理"
- 说"录入合同并生成报价单/发货单/派工单"
- 说"合同一条龙"、"走合同流程"
- 要求将合同"入 base + 出单据"

---

## 前置依赖

本工作流依赖以下四个底层 skill，执行时按需调用：
| 步骤 | Skill 名 | 作用 |
|------|---------|------|
| 录入Base | `contract-to-base` | 提取合同信息，查重后录入飞书多维表格 |
| 报价单 | `contract-to-quote` | 生成标准 Word 报价单 |
| 发货单 | `contract-to-delivery-note` | 生成标准 Word 发货单 |
| 派工单 | `production-dispatch-order` | 生成标准 Excel 派工单 |

> ⚠️ 执行前**先读取** `workflow_config.yaml`，获取当前步骤列表和参数配置。后续所有步骤信息均以配置文件为准。

### 输出目录规则（全局统一）

**所有产出文件必须放入以合同文件名命名的文件夹中。**

- 合同文件示例：`SST-2026-06-003.pdf`
- 输出目录：`./output/SST-2026-06-003/`
- 每个 skill 生成文件时，**文件名保持原有命名规则不变**，但保存路径指向上述目录

> **规则**：
> - 若目录已存在，直接使用；若不存在，自动创建
> - 合同文件名去除扩展名后作为文件夹名
> - 若文件名含非法字符（`\ / : * ? " < > |`），替换为下划线 `_`
> - Base 录入操作不涉及本地文件输出，跳过此规则

## 阶段一：确认执行模式

**工作流正式开始前，必须向用户展示以下选项，等待用户明确选择。**

> 📋 **合同全链路处理工作流**
>
> 检测到合同文件，我将按以下步骤处理：
> 1. 📊 录入合同到飞书多维表格（查重+建档）
> 2. 💰 生成 Word 报价单
> 3. 🚚 生成 Word 发货单
> 4. 🔧 生成 Excel 派工单
>
> **请选择执行模式：**
> - **A. 全套执行** — 自动连续执行所有步骤，中间不再提问，直到产出所有文件
> - **B. 局部执行** — 您可以勾选要执行的步骤，每个步骤可补充额外信息

**规则：**
- 用户未明确选择前，**禁止开始任何步骤**
- 若用户说"全部"、"全套"、"都来"、"A" → 进入全套执行
- 若用户说"局部"、"选几个"、"B" → 进入局部执行
- 若用户只上传文件没说话 → 主动询问，等待答复

---

## 阶段二-A：全套执行模式

**原则：零提问，全自动，一气呵成。**

### 执行流程

1. **创建输出目录**：根据合同文件名生成 `./output/{合同文件名}/` 目录
2. **读取配置**：从 `workflow_config.yaml` 获取步骤列表和参数
3. **按顺序执行**（步骤 1 → 2 → 3 → 4）：
   - 每一步调用对应的底层 skill
   - 上一步的输出数据自动注入下一步的输入
   - 每个生成文件的 skill（quote / delivery / dispatch）必须将文件保存到输出目录
4. **不中断**：即使某一步出现警告（如"参考询价"），也继续执行后续步骤
5. **一次性汇报**：全部完成后，汇总所有产出文件和关键信息

### 跨步骤数据传递规则

| 传递方向 | 数据内容 | 说明 |
|---------|---------|------|
| base → quote | 采购方、合同金额、产品清单、原始合同编号 | 报价单的客户名、单号、物料 |
| base → delivery | 采购方、销售方、产品清单 | 发货单的收发货单位、物料 |
| base → dispatch | 采购方、产品清单 | 派工单的使用方、订单内容 |

> **数据传递方式**：上一步执行完毕后，将其输出字段值整理为 key-value 结构，作为下一步 skill 调用的上下文参数。具体字段名以 `workflow_config.yaml` 的 `data_flow` 节为准。

### 全套执行时的用户交互（禁止提问）

- ❌ 不询问 base-token / table-id（使用默认值或 skill 内部处理）
- ❌ 不询问历史参考合同（不提供则全部标"参考询价"）
- ❌ 不询问收货人/交货地点（从合同中提取，提取不到则按 skill 默认值）
- ❌ 不在步骤间停顿（上一步完成立即执行下一步）

## 阶段二-B：局部执行模式

**原则：用户主导，步骤可选，信息可补。**

### Step 1：让用户勾选步骤

展示所有可用步骤（带默认勾选状态）：

> 📋 **请选择要执行的步骤**（多选）：
> - [x] ① 录入合同到多维表格 — 提取信息并录入飞书 Base
> - [x] ② 生成报价单 — 输出 Word 报价单
> - [x] ③ 生成发货单 — 输出 Word 发货单
> - [x] ④ 生成派工单 — 输出 Excel 派工单
>
> 请告诉我您要执行的步骤编号，或取消某些步骤。

**规则：**
- 用户可勾选全部、部分、或只选一个
- 若用户取消某步骤，该步骤**完全不执行**
- 但注意：quote / delivery / dispatch 都依赖 base 的输出数据
  - 若用户**勾选了 quote/delivery/dispatch 但未勾选 base**，必须先执行 base，或者将 base 的执行结果作为必需前提告知用户
  - **处理方式**：向用户说明"生成报价单/发货单/派工单需要先从合同提取信息，是否同时执行步骤①？"，获得确认后再开始

### Step 2：逐个执行选中的步骤

对**每个选中的步骤**，按以下子流程执行：

```
┌─────────────────────┐
│ 展示该步骤补充信息提示 │  ← 来自 workflow_config.yaml 的 supplement_prompts
│ 询问用户有无补充      │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ 用户确认/补充信息    │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ 合并信息：           │
│   配置文件默认值      │
│ + 前序步骤输出数据    │
│ + 用户补充信息        │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ 调用对应底层 skill   │
│ 执行该步骤           │
│ （生成文件的步骤      │
│  保存到输出目录）     │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ 汇报该步骤结果       │
│ 询问是否继续下一步   │  ← 若还有未执行的选中步骤
└─────────────────────┘
```

**用户补充信息的合并优先级（高→低）：**
1. 用户补充的信息（最高优先级）
2. 前序步骤的输出数据
3. 配置文件中的默认值
4. skill 内部默认值

> **示例**：用户补充"收货人：张三，电话：13800138000"
> → 在生成发货单时，即使合同中未提取到收货人信息，也优先使用用户补充的值。

## 扩展与调整指南

### 增加新步骤

编辑 `workflow_config.yaml`：
1. 在 `steps` 列表末尾追加新步骤定义
2. 在 `data_flow` 中声明数据依赖关系
3. 在 `supplement_prompts` 中追加补充信息提示模板

**无需修改 SKILL.md。**

### 调整步骤顺序

编辑 `workflow_config.yaml` 中 `steps` 列表的顺序即可。
注意：quote / delivery / dispatch 默认依赖 base 的输出，调整顺序时需同步调整 `data_flow`。

### 修改补充信息提示

编辑 `workflow_config.yaml` 中 `supplement_prompts` 对应步骤的文本即可。

### 增加全局输入

编辑 `workflow_config.yaml` 中 `global_inputs` 列表，新增输入项会在工作流启动时自动收集。
