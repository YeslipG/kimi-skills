# 销售设备付款审批

在 OA 中完成「取合同编号 → 关联合同 → 提前校验到款 → 填付款信息 → 截图 → 提交 → 已办核验」。减少浏览器试错和调用次数，但不减少业务核验。真实提交会发起审批，只有用户明确要求发起、提交或申请付款时才执行最后提交；若用户只要求填表，停在提交前。

## 输入与默认值

- 用户上传或指定的合同文件：必需，用于解析合同编号；执行前重新读取磁盘上的文件名和内容，以当前文件为准。
- `payment_ratio`：付款比例（%），默认 `100.00`。
- `remark`：备注，默认 `26年配件跳汰所到款申请付款`。
- 付款内容：固定选择 `到货款`。
- 多份合同按文件逐份串行处理，不并行提交；每份记录为“已办已核验 / 到款不足未提交 / 数据异常未提交 / 提交结果未核实”。

## 合同编号规则（最高优先级）

合同编号只能取自文件名开头、以 `GHI` 开头的编号，不能取任务文字、合同正文或其他位置的编号。

按文件名起始位置匹配：

```text
^GHI-\d+-\d+-\d+
```

例如：

```text
GHI-2026-29-075-260518-hpgh-益海嘉里(周口)生物科技有限公司-28000-BGJ-2026-31-117.jpg
→ GHI-2026-29-075
```

后面的日期、公司简称、金额及 `BGJ-...` 均不属于合同编号。文件名中的 `BGJ-...` 只能用于核对联动出的销售合同编号。若文件名不匹配、解析结果不唯一或搜索不到合同，先重新核对文件名；仍无法解决则停止并向用户确认，不得改用任务文字或正文中的其他编号。

## 浏览器准备：本机 Edge 快速路径

用户已明确本机 OA 登录态在 Edge。处理本机此 OA 时直接使用 `kimi-webbridge`，不要先在内置浏览器等待或重复确认登录态；用户或当前运行环境明确指定其他浏览器时，按对应要求执行。

1. 每个批量任务只使用一个 WebBridge `session` 和一个标签组，不要在合同之间切换 session。复用本任务已经打开的门户和销售付款标签页，不为每份合同重开首页或创建页。
2. 连接被拒绝时，按 `kimi-webbridge` skill 启动本地 daemon；若提示 `extension_not_connected`，让用户在 Edge 启用/连接扩展后继续。不要尝试获取或填写密码。
3. 首次打开门户并确认已登录：
   `http://114.116.12.172:8899/wui/index.html#/main/portal/portal-10-15`。后续已办核验只刷新这个已有门户标签。
4. 当前已经在销售付款创建页时直接复用；只有没有可用创建页时，才用本 skill 已验证的完整创建地址打开一次。完整地址和脚本见 [references/edge-fast-path.md](references/edge-fast-path.md)，使用 Edge 时先读取该文件。不要反复点击“销售付款”快捷入口、轮询标签页或尝试多组鼠标事件。
5. 确认页面标题为「创建 - 销售设备付款审批表」且 URL 含 `workflowid=108`。若直接地址返回“无权限”，回已有门户读取快捷入口配置中的真实链接一次，以其为准；不要继续盲目点击。

Windows 下 WebBridge 请求仍按 `kimi-webbridge` skill 使用独立临时 JSON 文件和 `curl.exe` 文件请求体，并在返回后删除临时文件。为减少往返，把同一阶段的 DOM 操作合并到一次 `evaluate`，不要为每次点击、填值和读值单独发请求。

## 操作步骤

### 1. 打开创建页并关联合同

复用当前销售付款创建页，按 [references/edge-fast-path.md](references/edge-fast-path.md) 的“合同关联模板”一次完成。上一份提交后页面仍保留时，原地刷新为空白创建页再继续下一份，不要新建标签页：

1. 点击「合同编号」旁的搜索按钮，打开「合同编号LC」。
2. 在弹窗第一个「合同编号」输入框填入从文件名解析出的编号并搜索。
3. 只点击「合同编号」列完全匹配的合同行，不选择名称相近或部分匹配的行。
4. 等待联动完成，核对合同名称、合同金额（万元）、上级合同编号、付款单位、收款单位、开户银行、收款账号、销售合同编号、已到款金额（万元）等字段。不要手填这些联动字段。
5. 合同金额、收款单位或已到款金额为空、明显异常或与所选合同不符时，停止该单并报告，不要提交本单；批量任务可刷新当前创建页，清空本单数据后继续下一份，只有页面异常无法复用时才关闭。

### 2. 关联后立即校验到款，失败提前停止

在选择付款内容和填写比例之前，先读取合同金额与已到款金额，使用十进制数值判断：

```text
已到款金额（万元） ≥ 合同金额（万元） ÷ 0.8
```

不满足时立即停止本单，明确展示合同金额、已到款金额、最低要求金额及差额。此时不要继续修付款比例、截图或点击提交；批量任务刷新当前创建页后继续下一份。这样可把无资格提交的合同尽早排除，同时保留页面供后续合同使用。

### 3. 一次完成付款内容、备注和比例联动

仅在第 2 步通过后，按参考文件的“付款信息模板”一次完成并读回：

- 「付款内容」是自定义下拉组件：展开后点击「到货款」，再读取可见值，确认不是其他款项。
- 备注写入 `textarea#field6527`。
- 付款比例写入 `input#field8896`，默认 `100.00` 或用户指定值。

普通 `fill` 或同步集中派发事件可能把比例重置为 `0.00`。Edge 快速模板采用已验证的异步顺序：聚焦并等待 → 原生 value setter + `input` → 等待 → `keyup` + `change` → 等待 → `blur` → 等待联动 → 重新读取。不要只确认输入动作已发送。

若使用内置浏览器，优先点击字段、全选输入并按 `Tab` 失焦，再读回验证。无论使用哪种浏览器，比例被重置或金额未正确联动时都不得提交。

核验可见的「本次付款金额(万元)」（`id=field8269`）：

```text
预期本次付款金额（万元） = 合同金额（万元） × 付款比例（%） ÷ 100
```

按页面显示精度核对，允许正常的末位四舍五入误差。`field8268` 是以元为单位的隐藏域，不要用它替代 `field8269`。脚本返回的 `pass` 必须显式包含“比例等于目标值”，避免比例为 0 时被误判为通过。

### 4. 提交前复核并截图

再次读取页面，确认：

- 合同编号与文件名完全一致，销售合同编号及联动单位正确；
- 付款内容为「到货款」，备注正确；
- 比例等于目标值，本次付款金额符合公式；
- 已到款条件仍满足，关键字段不为空。

任一条件不满足都不得提交。

【必做】点击「提 交」前，对当前完整提交页面截图并保存到：

```text
C:\Users\yesli\Desktop\销售设备付款审批表_<合同编号>_<申请日期>.png
```

申请日期使用表单中的申请日期；文件名日期采用 `YYYY-MM-DD`。截图应能辨认合同编号、收款单位、付款比例、本次付款金额和备注。保存后用图片读取工具检查截图内容与清晰度；必要时滚动补充截图，但至少保留一张提交前完整页面图。未成功留档前不要提交。

### 5. 提交审批

1. 确认必填项齐全、校验通过且截图已留档，再点击页面右上角「提 交」。
2. 若出现信息确认弹窗，阅读内容；确认业务数据无误后按提示确认。若提示校验失败或数据异常，不要强行继续，记录错误并报告。
3. 无弹窗残留且页面提交完成后才进入已办核验；不要仅凭点击动作或页面关闭宣称成功，也不要因结果暂不可见而重复提交。
4. 批量任务优先复用当前销售付款页面：提交后原地刷新为空白创建页，再继续下一份。若创建页自动关闭，则复用本任务已有标签进入创建页，不新开标签。

### 6. 已办事宜核验：直接整页刷新

1. 切换到本任务已经打开的门户标签并整页重新加载，不要重新打开首页，也不要先对“已办事宜”做多次局部刷新。核验后返回已有销售付款标签继续处理。
2. 查找新流程，标题形如：`销售设备付款审批表-<申请人>-<日期>(收款单位:…, 本次付款金额(万元):…)`。
3. 核对申请人、日期、收款单位和本次付款金额。金额按数值比对，兼容 `0.8`、`0.80` 等等价显示；同时核对新记录时间或提交前列表，避免把历史同金额流程误认为本单。
4. 若未出现，再整页刷新一次并检查错误提示。仍查不到时报告“提交结果未核实”，不要宣称成功或重复提交。批量任务可在后续整页刷新时一并复核前面未核实的记录。

## 完成汇报

简要汇总每份合同：

- 合同编号及文件名来源；
- 处理状态；已提交时给出付款内容、比例、收款单位、本次付款金额（万元）和已办新流程标题；
- 已到款校验结果；未提交时给出最低要求、实际已到款和差额；
- 提交前截图路径；未提交的合同不伪造截图或成功记录。

最后核对临时请求文件已删除。用户未要求时不要关闭整个 Edge 标签组。
