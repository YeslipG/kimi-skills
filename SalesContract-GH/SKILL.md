# SalesContract-GH：国华销售合同生成

## 适用场景

用户手上有两样东西：
1. **合同模板**：一份已签订的《工矿机械产品买卖合同》Word（.doc/.docx），包含条款框架、签署栏版式。
2. **报价单/说明材料**：本次交易的物料清单、价格、交货期、买卖双方联系方式等（.doc/.docx/PDF/图片）。

输出一份格式与模板一致的新合同 Word 文档，只替换必要内容（标的物、金额、日期、联系方式等），保留模板原有条款文字和排版。

## 输入要求

执行前必须向用户确认或从文件中提取：
- 模板文件路径（`.doc` 或 `.docx`）
- 报价单/说明材料文件路径（`.doc`、`.docx`、`.pdf` 或图片）
- 签订日期（如用户说“今天”，取本机当天日期）
- 合同编号（如用户未指定，沿用模板格式，将日期部分替换为当天）

## 输出

- 一份 `.docx` 格式销售合同，保存到 `D:/Kimi/output/`。
- 按项目 AGENTS.md 强制规则，额外复制一份同名副本到 `C:/Users/yesli/OneDrive/桌面`。

## 执行流程

1. **格式转换**
   - 若模板或报价单为 `.doc`，先用 `scripts/convert_doc.py` 转换为 `.docx`：
     ```bash
     python scripts/convert_doc.py <输入.doc> <输出.docx>
     ```
   - 若报价单是 PDF/图片，用 `ReadMediaFile` 或渲染为图片查看内容。

2. **读取模板结构**
   - 用 `python-docx` 读取模板，确认：
     - 抬头段落（出卖方、买受方、合同编号、签订地点、签订时间）
     - 标的表格列数、表头、金额行位置
     - 签署栏段落结构
   - 如果模板结构与典型国华合同不同（如无“第十七条”或签署栏不是 9 段），按实际模板调整，不要硬套。

3. **提取报价单信息**
   - 从报价单中读取：
     - 出卖方（报价单位）、买受方（客户名称）
     - 出卖方地址、联系人、电话、传真
     - 标的物明细（名称、型号规格、单位、数量、单价、总价、备注）
     - 合计金额
     - 付款方式、交货期、税率、运费说明

4. **生成配置 JSON**
   - 在临时目录写入 `config.json`，包含提取出的全部字段。
   - 示例见 `references/config-example.json`。

5. **生成合同**
   - 运行：
     ```bash
     D:/Kimi/.venv-xlsx/Scripts/python.exe scripts/build_contract.py <config.json>
     ```
   - 脚本会基于模板生成新合同，替换抬头、标的表格、金额、签署栏信息。

6. **交付前检查**
   - 用 Word 或导出 PDF 预览，确认：
     - 合同编号、签订日期已更新
     - 标的表格内容与报价单一致
     - 金额大小写正确
     - 旧模板信息（原金额、原日期、原标的物、原联系方式）无残留
     - 页面无严重错位，签署栏完整
   - 复制最终 `.docx` 到桌面并核对文件大小。

## 注意事项

- **模板第一优先**：严格按照模板版式生成，不擅自添加封面、目录、三色标注等额外元素，除非用户明确要求。
- **旧值必须清除**：生成后必须检查旧合同编号、旧金额、旧日期、旧标的物、旧出卖方地址/电话是否已替换。
- **签订日期**：用户说“今天”时，用 `date +%Y-%m-%d` 取本机真实日期，不要依赖会话时间。
- **合同编号**：若用户未指定，沿用模板编号格式，仅把日期部分替换为当天（如 `GHJH20260228` → `GHJH20260725`）。
- **传真**：模板如无传真行，在签署栏“电话”行后插入“传真”行。
- **金额行合并单元格**：模板金额行通常为合并单元格，设置时只写第一个单元格，避免覆盖清空。

## 依赖

- Python 环境：`D:/Kimi/.venv-xlsx/Scripts/python.exe`（含 `python-docx`、`pywin32`）
- Microsoft Word（用于 `.doc` 转换和刷新域）
