# 专业发货单生成专家

从合同PDF或图片的OCR结果中提取关键信息，生成符合"专业排版V2版"标准的Word发货单。

## 触发条件

当用户请求以下任务时触发此技能：
- 将合同转换为发货单/送货单
- 根据合同生成发货单
- 从合同PDF提取信息制作发货单
- 上传合同并要求生成Word发货单
- 直接上传合同文件（PDF/图片）并要求处理

## 核心任务

1. **信息提取**：从OCR结果中提取需方、物料清单、交货地点、收货人及联系电话等关键信息
2. **排版生成**：按"专业排版V2版"标准生成Word发货单，确保字体、字号、颜色、间距和表格样式统一
3. **业务校验**：校验提取信息是否符合业务规则（如发货单位正确、物料备注栏不为空等）

## 执行工作流

### Step 0：信息来源与识别方式

根据用户上传的文件类型，选择最优识别路径：

| 文件类型 | 识别方式 | 说明 |
|----------|----------|------|
| **PDF** | 1. 先用 `PyMuPDF (fitz)` 将每页渲染为高清图片（建议 1.5x~2x 缩放，保证文字清晰）；<br>2. 再使用 **Kimi 视觉模型**逐页读取图片并提取文字和表格内容。 | 严禁默认使用本地 PaddleOCR / pytesseract 等低精度 OCR 工具作为首选方案。 |
| **图片** | 直接使用 **Kimi 视觉模型**读取原图。 | 若图片模糊或文字过小，可提示用户重新截图或调高分辨率。 |

**核心原则**：视觉模型识别中文表格及复杂排版的准确度远高于传统 OCR 代码方案，尤其是包含多行数字、竖排文字或嵌套单元格的合同表格。

### Step 1：信息提取

从视觉模型识别的结果（或用户提供的OCR结果）中提取以下字段：

#### 1. 合同编号
- **优先从合同内容提取**：查找"合同号"或"合同编号"后的内容
- **次选从文件名提取**：若合同内容中无合同号，从PDF/图片文件名中提取10位以上数字串（只提取数字）
- 若仍无，显示"无"

#### 2. 需方（收货单位）
- 提取"需方:"或"收货单位:"后的内容
- 若无，显示"无法识别"

#### 3. 供方（发货单位）
- 提取"供方:"或"发货单位:"后的内容
- **必须校验**：若非以下三家之一，报错"错误的发货单位"：
  - 北京国华技术有限公司
  - 北京国华科技集团有限公司
  - 南通厚普机械科技有限公司

#### 4. 物料清单
- **优先从HTML表格提取**：若OCR结果含 `<tr>`、`<td>`，按表格结构提取
- **次选从纯文本提取**：按"序号 物料编码 物料名称 数量"模式提取，分离规格型号、单位、单价、金额
- **关键字段**：
  - 编码（这不是规格，如无此内容，则显示"无"）
    - **重要复核**：若合同表格中的编码单元格采用垂直/多行排列（如第一行 `81463`、第二行 `10000`、第三行 `25`），**必须将多行数字全部提取并原样保留**，不可仅取第一行。
  - 名称
  - 规格型号（如和名称连在一起，则从名称中分离）
  - 数量（仅数字，不含单位）
  - 单位（件/台/套/块等）
  - 备注（来源于表格第8列或特定标识，如"使用部门""货位"，若原合同为空则填"-")
- **必填校验**：每条物料"备注"栏不能为空，否则报错

#### 5. 交货地点
- 提取"交货地点:"后的内容
- 若无，显示"无法识别"

#### 6. 收货人/电话
- 提取"收货人:"和"联系电话:"后的内容
- 若无，分别显示"无法识别"

### Step 2：业务逻辑校验

生成发货单前必须校验：

| 校验项 | 规则 | 错误处理 |
|--------|------|----------|
| 发货单位 | 必须为预设三家公司之一 | 报错："错误的发货单位" |
| 物料备注 | 每条物料的"备注"栏不能为空 | 报错："物料备注不能为空" |
| 表格列数 | 输出表格必须为7列 | 报错："表格列数不符合规范" |

**重要**：若校验不通过，**不生成不完整文档**，需清晰报告错误信息。

### Step 3：生成Word发货单

按"专业排版V2版"标准创建Word文档：

#### 字体与字号
- 中文字体：微软雅黑
- 英文/数字字体：Arial
- 标题字体：黑体
- 字号：
  - 一级标题（发货单）：18pt
  - 二级标题/正文标签：14pt（或11pt加粗）
  - 正文内容：11pt
  - 表格内容：10pt

#### 段落与布局
- 行距：1.5倍
- 段前段后间距：6pt
- 页边距：上/下 2.54cm，左/右 3.17cm
- 对齐方式：标题居中，标签左对齐，表格内容智能对齐（序号和数量居中）
- 表格单元格边距：0.1cm

#### 表格样式
- 边框：所有边框（含内部）为0.5pt单实线，蓝色
- 表头：浅蓝背景（D9E1F2），文字加粗，居中对齐
- 合计行：浅黄背景（FFF2CC），文字加粗
- 列结构：7列，分别为"序号"、"物料编码"、"物料名称"、"规格型号"、"数量"、"单位"、"备注"
- **重要**：表格中不得包含任何价格信息（单价、金额、总价等）

#### 文档结构

```
【标题】发货单（居中，18pt，黑体，深蓝）

【发货单位】
发货单位：[提取的供方名称]

【收货单位】
收货单位：[提取的需方名称]

【合同编号】
合同编号：[提取的合同号或显示"无"]

【物料表格】
| 序号 | 物料编码 | 物料名称 | 规格型号 | 数量 | 单位 | 备注 |
|------|----------|----------|----------|------|------|------|
| 1    | ...      | ...      | ...      | ...  | ...  | ...  |
| ...  | ...      | ...      | ...      | ...  | ...  | ...  |
| 合计 |          |          |          | XX   |      |      |（合并前4列，数量列显示总数，背景浅黄色）

【交货信息】
交货地点：[提取的地点]
收货人：[提取的收货人]
联系电话：[提取的收货人电话]
```

### Step 4：代码实现要点

- 使用 `run` 级别设置中英文字体，确保混排正确
- 通过 `OxmlElement` 精细控制表格边框、背景色、单元格边距等高级样式
- **文件名格式**：`{日期}_发货单_{收货单位核心名称}.docx`，日期格式为6位数字（如260320），置于最前方
- 日期生成格式：`datetime.now().strftime('%y%m%d')`
- **收货单位核心名称提取规则**：
  1. 去除开头的省市名（如"北京"、"上海"、"江苏省"、"广东省"等）
  2. 去除结尾的"有限公司"、"有限责任公司"、"股份公司"等后缀
  3. 保留核心名称部分
  4. 示例：
     - "上海电气集团股份有限公司" → "电气集团"
     - "江苏省某某科技有限公司" → "某某科技"
     - "北京国华技术有限公司" → "国华技术"
- 严格遵循排版规范，杜绝字体、颜色、间距不一致问题

## 错误处理与默认值

| 场景 | 处理方式 |
|------|----------|
| OCR失败 | 清晰报告错误信息，不生成文档 |
| 信息提取不完整 | 报告缺失字段，不生成不完整文档 |
| 校验不通过 | 报告具体校验错误，不生成文档 |
| 无法提取信息 | 使用预设默认值（如"无法识别""无"），并明确告知用户 |

## 输出格式

- **格式**：Word文档（.docx）
- **文件名**：`{日期}_发货单_{收货单位核心名称}.docx`
  - 日期格式：6位数字（年月日），如260320
  - 日期位置：文件名最前方
  - 收货单位核心名称：去除省市前缀和公司后缀后的核心名称
- **内容**：符合"专业排版V2版"标准的完整发货单，或详细的错误报告

## 示例流程

1. **输入**：合同PDF的OCR结果（含HTML表格或纯文本）
2. **处理**：
   - 提取合同编号、需方、供方、物料清单（分离数量和单位）、交货地点、收货人/电话
   - 校验发货单位、物料备注、表格列数
3. **生成**：
   - 按排版规范创建Word文档，填充提取信息
   - 添加标题、发货单位、收货单位、合同编号、物料表格（7列，序号自增）、交货信息
   - 文件名格式：`260413_发货单_电气集团.docx`（假设收货单位为"上海电气集团股份有限公司"）
4. **输出**：符合标准的Word发货单或错误报告
